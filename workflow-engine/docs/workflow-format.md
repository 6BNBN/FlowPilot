# 工作流 Markdown 格式规范

## 基本结构

工作流定义文件为 `.md` 格式，包含标题和步骤列表。

```markdown
# 工作流名称

1. 第一步描述
2. 第二步描述
3. 第三步描述
```

## 步骤编号

- 数字 `1, 2, 3` 表示**串行**执行，按顺序依次推进

## 并行步骤

用子列表 + 字母后缀表示并行：

```markdown
2. 并行阶段
   2a. 任务A（与2b同时执行）
   2b. 任务B（与2a同时执行）
   2c. 任务C（与2a/2b同时执行）
```

所有子步骤完成后才进入下一步。

## 控制流标记

### [loop] 循环

```markdown
3. [loop] 重复执行直到满足条件
   - condition: {{变量}} == "完成"
   3a. 循环体操作
   3b. 检查结果
```

condition 为终止条件，满足时退出循环。

### [branch] 分支

```markdown
4. [branch] 根据条件选择路径
   - condition: {{状态}}
   - "成功": 5
   - "失败": 6
   - default: 7
```

根据 condition 的值跳转到对应步骤。

### [factory] 子流程派生

```markdown
5. [factory] 为每个子项派生子流程
   - workflow: ./子流程.md
   - items: {{列表变量}}
```

为 items 中每个元素创建独立的子流程实例。

## 完整示例

```markdown
# 代码审查流程

1. 接收代码提交
2. 并行检查
   2a. 运行单元测试
   2b. 静态代码分析
   2c. 安全扫描
3. [branch] 检查结果
   - condition: {{检查通过}}
   - "true": 4
   - "false": 5
4. 合并代码，流程结束
5. [loop] 修复问题
   - condition: {{问题已修复}} == "true"
   5a. 通知开发者修复
   5b. 等待修复提交
```
